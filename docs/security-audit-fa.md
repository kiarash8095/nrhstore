# گزارش بررسی امنیت، باگ و پاک‌سازی فروشگاه

تاریخ: ۲۰۲۶/۱۰/۲۳ — پروژه کیارش افروغ. این گزارش وضعیت کد محلی پس از اصلاحات را توضیح می‌دهد. شواهد اجرای همین بررسی در `artifacts/security-audit` ذخیره شده‌اند.

بررسی از افزودن محصول شروع شد و ورود، انتقال سبد مهمان، تغییر تعداد، کوپن، آدرس، ارسال، شروع پرداخت و نمایش نتیجه سفارش را پوشش داد. **روی سایت واقعی فقط API خوانده شد؛ پیامک، تغییر سبد واقعی، سفارش و پرداخت واقعی انجام نشد.**

| مسیر بدون مصرف‌کننده ساخت پیش‌نویس | endpoint قدیمی `/api/cart/checkout` می‌توانست پیش‌نویس اضافی بسازد. | مسیر، تابع کلاینت و شاخه سرور حذف شدند. جریان فعلی فقط از `/api/cart/pay` استفاده می‌کند. تست HTTP پاسخ ۴۰۴ مسیر قدیمی را بررسی می‌کند. |

پارامتر `success=true` در مرورگر پرداخت را موفق نمی‌کند. مبلغ، مالک سفارش، توکن بانکی و شواهد Verify باید در سرور معتبر باشند. تکرار callback، قطع ارتباط و درخواست پرداخت تکراری در تست‌های PHP و Node بررسی شده‌اند.

شواهد کلیدی: `final-node.tap`، `wordpress-after.txt`، `http-development.json`، `http-production.json`، `browser-development/browser-results.json`، `browser-production/browser-results.json` و `client-secret-scan.json`.

بانک و APIهای تغییردهنده در تست مرورگر intercept شدند. تست PHP از doubles استفاده می‌کند و به دیتابیس واقعی وصل نمی‌شود. این دو سطح، منطق برنامه را بررسی می‌کنند؛ پذیرش درگاه و سازگاری نسخه نصب‌شده وردپرس با تست واقعی محیط آزمایشی مشخص می‌شوند.

## موارد باقی‌مانده در سایت و زیرساخت

1. **رابط وردپرس روی سایت واقعی در دسترس نیست.** در فهرست REST، مسیرهای checkout، انتقال سبد، callback و وضعیت سفارش `nrh/v1` پیدا نشدند. تا نصب و تنظیم رابط، جریان جدید انتقال سبد و پرداخت واقعی کامل نمی‌شود. ZIP آماده: `artifacts/payments/nrh-headless-checkout.zip`، نسخه ۱٫۱٫۱. نصب فقط از روی کد محلی قابل تأیید نیست.
2. مبدأ فرانت در `NRH_HEADLESS_FRONTEND_URL` باید تنظیم شود. طبق روش فعلی افزونه، این کار در `wp-config.php` انجام می‌شود؛ با دسترسی صرفاً پنل، برای این تنظیم به پشتیبانی هاست نیاز است. راهنمای نصب در [راهنمای سداد](headless-checkout-sadad-fa.md) آمده است.
3. مسیرهای خصوصی auth، cart، checkout و payments باید از کش وردپرس و CDN مستثنا شوند. خواندن سبد با URL یکتا در بررسی حاضر پاسخ ۲۰۰ و cache miss داد. این مشاهده جای تنظیم دائمی استثناهای کش را نمی‌گیرد.
4. در نمونه ۲۰ محصول ساده موجود، محصولات **۱۶۷۶، ۱۶۶۷ و ۱۵۴۴** با وجود `is_in_stock=true`، مقدار `is_purchasable=false` و قیمت صفر داشتند. غیرفعال‌بودن خریدشان مطابق پاسخ ووکامرس است؛ قیمت و قابلیت خرید باید در پنل بررسی شوند. هیچ قیمت زنده‌ای تغییر نکرد.
5. پاسخ نامشخص بانک عمداً پرداخت‌شده تلقی نمی‌شود. سفارش نامشخص می‌تواند جلوی تلاش تازه را بگیرد تا برداشت تکراری رخ ندهد. برای پرداخت رهاشده، توکن منقضی و قطعی طولانی، روال تطبیق وضعیت سفارش با بانک باید در پذیرش محیط آزمایشی بررسی شود؛ این بررسی شامل پرداخت واقعی نبود.
6. **۵ هشدار High در وابستگی‌های ابزار توسعه** باقی است؛ مربوط به زنجیره braces/micromatch/fast-glob و ESLint است. در گزارش وابستگی production هشدار باقی نمانده است. رفع زنجیره توسعه به وصله سازگار بالادستی نیاز دارد؛ نسخه ابزار هماهنگ با Next فعلی حفظ شد.
7. محدودساز درخواست‌ها در حافظه هر پردازش است. قفل و ابطال نشست به فضای فایل پایدار و مشترک وابسته‌اند. استقرار چندسروری بدون فضای مشترک، به ذخیره و محدودسازی توزیع‌شده نیاز دارد. پراکسی میزبان باید هدر IP را بازنویسی کند.
8. ارسال و مصرف واقعی OTP، تحویل ایمیل و ابطال نشست‌های دستگاه‌های دیگر همچنان به رفتار Boom و تنظیمات وردپرس وابسته‌اند. در این بررسی حساب واقعی یا رمز کاربر تغییر نکرد.
9. در کنسول development هنگام بازشدن خودکار مودال ورود روی صفحه دارای بخش‌های stream‌شده، هشدار اختلاف attributeهای `aria-hidden` و inert مشاهده شد. آزمون‌های فرم و مسیر خرید نهایی موفق شدند؛ این هشدار ظاهری هنوز نیازمند بررسی جداگانه زمان‌بندی hydration مودال و بخش‌های دیررس است.
10. سرور dev قدیمیِ از قبل باز را برای بارگذاری نسخه‌های جدید **restart کنید**. npm نتوانست فایل native قدیمیِ در حال استفاده در پوشه موقت `node_modules/@next/.swc-win32-x64-msvc-ZrbcVY5L` را حذف کند؛ حدود ۱۳۰٫۵MiB باقی مانده است. کد و lockfile نسخه جدید را دارند؛ سرور قدیمی تا restart لزوماً آن نسخه را اجرا نمی‌کند. وضعیت حذف در `native-cleanup.json` ثبت شده است.

## پاک‌سازی انجام‌شده

گزارش‌ها و تصاویر قدیمی auth/cart/banner/layout/race و خروجی قدیمی مقایسه محیط‌ها حذف شدند. حدود **۵۰۳MiB** خروجی قدیمی حذف شد؛ فهرست و اندازه دقیق در `cleanup.json` آمده است. خروجی ساخت و کش‌های موقت همین بررسی پس از پایان آزمون حذف شدند؛ جزئیات در `temporary-cleanup.json` آمده است. گزارش‌ها و تصاویر نهایی این بررسی حفظ شده‌اند.

فایل‌های خالی WooCommerce، hook قدیمی محصولات، hookهای بدون مصرف swipe/drag، مثال نمایشی Rating، دو آیکون بدون ارجاع و مسیر پیش‌نویس قدیمی حذف شدند. تست‌ها، مستندات، داده عملیاتی و PDF راهنمای فارسی حفظ شدند. فایل‌های دارای ارجاع واقعی در بررسی TypeScript حفظ شدند.

وابستگی `cn` با تابع موجود `lib/utils.ts` یکسان شد. CLI بسته shadcn حذف شد؛ CSS موردنیاز همان نسخه همراه مجوز MIT در `styles/vendor/shadcn` باقی است تا ظاهر و حالت‌های کامپوننت‌ها حفظ شوند. این فایل از بسته اصلی گرفته شده و هش آن در README همان پوشه ثبت شده است.

تست‌های زنده تغییردهنده اکنون علاوه بر تنظیمات قبلی به `NRH_ALLOW_LIVE_MUTATIONS=1` نیاز دارند. تست auth مرورگر، نوشتن‌های تعریف‌نشده را محلی مسدود می‌کند. این کار از اجرای اتفاقی تستی که پیامک یا سبد واقعی را تغییر دهد جلوگیری می‌کند.

## اجرای دوباره

```sh
npm run test:auth
npm run test:cart
npm run test:payments
npm run test:payments:wordpress
npm run test:headless
npm run test:environment
npm run test:race:locks
node --test tests/security/*.test.cjs
npm run lint
npm run typecheck
npm run build
npm run start
```

برای HTTP، `SECURITY_TEST_URL` را به سرور محلی خود بدهید و `npm run test:security:http` را اجرا کنید. این مجموعه فقط درخواست‌هایی می‌فرستد که پیش از هر تغییر upstream رد می‌شوند.

برای مرورگر کنترل‌شده، `PAYMENTS_TEST_URL` مبدأ Next، `PLAYWRIGHT_MODULE` مسیر Playwright و در صورت نیاز `PLAYWRIGHT_CHANNEL` مرورگر است. `PAYMENTS_TEST_PRODUCT_SLUG` را از یک محصول ساده قابل خرید با حداقل تعداد ۱ بدهید تا شروع آزمون از صفحه محصول باشد. `AUDIT_ARTIFACT_DIR` مسیر خروجی را عوض می‌کند. بدون slug، آزمون از checkout شروع می‌شود. از تست‌های live برای تکرار بررسی فقط‌خواندنی استفاده نکنید.
