# رفع خطای سبد روی Vercel

این سند گزارش بررسی نسخهٔ ۱٫۲ است. نسخهٔ فعلی **۱٫۳**، هماهنگی سبد/پنل/پرداخت را روی تمام میزبان‌ها به وردپرس می‌سپارد، تعدادهای سبد را جمع می‌کند و نمایش سبد در پنل دارد. برای نصب فعلی از [راهنمای آمادگی خرید](purchase-readiness-fa.md) استفاده کنید.

تاریخ بررسی: ۲۰۲۶-۱۰-۳۰. نسخه افزونه موردنیاز: NRH Headless Checkout **1.2.0**.

## علت و بازتولید

در نسخه آنلاین، اولین `GET /api/cart` بدون کوکی ۲۰۰ بود و کوکی مهمان می‌ساخت. دومین درخواست با همان کوکی ۵۰۲ و `cart_unavailable` می‌داد. درخواست اول شناسه‌ای برای قفل نداشت؛ درخواست دوم و تمام درخواست‌های حساب/تغییر سبد وارد `mkdir(data/cart-locks)` می‌شدند. این مسیر در Vercel قابل نوشتن نیست. `/tmp` هم بین نمونه‌های Function مشترک نیست و جای قفل مشترک را نمی‌گیرد. [مستندات فایل‌سیستم Vercel](https://vercel.com/docs/functions/runtimes#file-system-support).

پاسخ ۴۰۱ `session_expired` از `/api/auth/session` برای مرورگر مهمان به معنی واردنبودن است. نمایش این پاسخ در Network به‌تنهایی خرابی سبد را اثبات نمی‌کند. اختلال احراز هویت سرور در BFF اکنون با کد اصلی خودش برمی‌گردد و به خطای مبهم سبد تبدیل نمی‌شود.

## اصلاح معماری

- مرورگر همچنان فقط API هم‌مبدأ Next را صدا می‌زند. کوکی احراز هویت رمزگذاری‌شده و HttpOnly است؛ Cart-Token فقط بین BFF و Woo جابه‌جا می‌شود. مهمان از Cart-Token و حساب از Cookie + X-WP-Nonce و Nonce مستقل Store API استفاده می‌کند. [قرارداد Cart-Token ووکامرس](https://developer.woocommerce.com/docs/apis/store-api/cart-tokens/).
- در Vercel، خواندن/تغییر سبد و تازه‌سازی وضعیت پرداخت صراحتاً هماهنگی را به وردپرس می‌سپارند. بقیه مصرف‌کنندگان `withCartLocks` خودکار از قفل خارج نمی‌شوند. میزبان Node معمولی قفل فایل مشترک قبلی را حفظ می‌کند.
- افزونه برای Store API دارای هدر `X-NRH-Cart-Lock: mysql-v1`، پیش از بارگذاری نشست از دیتابیس قفل می‌گیرد. شناسه مهمان از توکن با امضای معتبر استخراج می‌شود؛ حساب به nonce معتبر نیاز دارد. کلیدها با انتقال سبد، پرداخت و پاک‌سازی سبد مشترک هستند. قفل تا shutdown بعد از ذخیره Woo نگه داشته می‌شود و نشست پیش از تأیید پاسخ هم ذخیره می‌شود. [هوک REST وردپرس](https://developer.wordpress.org/reference/hooks/rest_pre_dispatch/).
- هر تغییر با GET سبد آغاز می‌شود. پاسخ موفق Woo باید هدر نسخه قفل را داشته باشد؛ نبود آن با `cart_lock_backend_missing` و ۵۰۳، پیش از ارسال تغییر، متوقف می‌شود. قفل شلوغ ۴۰۹ است. پاسخ گم‌شدهٔ تغییر خودکار تکرار نمی‌شود.
- Origin درخواست سرور از مقصد معتبر وردپرس ساخته می‌شود؛ کنترل Origin مرورگر در Next برقرار است. نشست/سبدی که افزونه دیگری زودتر بارگذاری کند با `cart_session_loaded_early` متوقف می‌شود تا داده قدیمی نوشته نشود.

## ترتیب به‌روزرسانی

1. ZIP نسخه 1.2.0 را روی همان وردپرسِ `WP_API_URL` نصب و افزونه موجود را جایگزین کنید. ایجاد افزونه دوم با نام دیگر لازم نیست. تنظیم `NRH_HEADLESS_FRONTEND_URL` قبلی حفظ شود.
2. مسیرهای خصوصی Store API سبد و `nrh/v1` را از کش WordPress/CDN مستثنا کنید. هدر `X-NRH-Cart-Lock` در مسیر BFF تا وردپرس و در پاسخ حذف نشود.
3. سپس کد Next را خودتان commit/push کنید. متغیر جدیدی لازم نیست؛ `VERCEL=1` را خود پلتفرم تنظیم می‌کند. `CART_LOCK_DIR` راه‌حل Vercel نیست.
4. روی سایت واقعی، سبد مهمان را دوبار بخوانید، یک کالا اضافه/کم/حذف کنید و پس از reload بررسی کنید؛ سپس ورود، انتقال سبد و همین عملیات را برای حساب بررسی کنید.

در این کار نصب روی وردپرس، commit، push و deploy انجام نشده‌اند. نتیجهٔ نهایی با نسخه نصب‌شده Boom و پایگاه‌داده واقعی پس از به‌روزرسانی افزونه باید بررسی شود؛ تست‌های با داده ساختگی جای این مرحله را نمی‌گیرند. هیچ سفارش یا پرداخت واقعی در بررسی ایجاد نمی‌شود.

## آزمون‌ها

Build production، TypeScript و lint موفق بودند. ۹۵ تست Node و ۴۹ تست PHP موفق شدند.

آزمون محلی BFF با ووکامرس واقعی و یک سبد مهمان مستقل، بدون حالت Vercel، خواندن اول/دوم، افزودن کالا، بازخوانی داده ذخیره‌شده، حذف و بازخوانی سبد خالی را با ۲۰۰ گذراند. زمان خواندن‌ها حدود ۰٫۷۵ تا ۰٫۹ ثانیه و افزودن/حذف با GET مقدماتی حدود ۱٫۷ ثانیه بود؛ این نمونه محدود، معیار عمومی سرعت نیست. سبد آزمون پاک شد. فعال‌کردن حالت Vercel با افزونه قدیمیِ فعلاً نصب‌شده، پیش از افزودن، ۵۰۳ `cart_lock_backend_missing` داد. بنابراین نصب افزونه و آزمون مهمان/حساب در حالت Vercel همچنان لازم است. گزارش بدون توکن در `artifacts/cart-audit/live-guest-results.json` قرار دارد.

`node --test features/cart/tests/cart.integration.cjs features/payments/tests/payments.security.cjs features/auth/tests/auth.security.cjs tests/race-conditions/cart-lock.test.cjs`

پوشش شامل درخواست دوم مهمان، تغییر/خواندن حساب، مسیر فایل غیرقابل‌استفاده در Vercel، نبود هدر افزونه قبل از تغییر، قفل شلوغ، عدم تکرار تغییر گم‌شده، حفظ nonceها، اختلال auth، پرداخت و قفل چندپردازشی Node است.

`node wordpress/tests/run.cjs`

آزمون‌های PHP شامل انتقال، پرداخت، چرخه قفل قبل از بارگذاری تا ذخیره/shutdown، رقابت دو درخواست، توکن جعلی، nonce نامعتبر، بارگذاری زودرس، نشست اشتباه، خطای ذخیره و حمل توکن ناسازگار هستند. این آزمون‌ها از WordPress/Woo/DB doubles استفاده می‌کنند و به فروشگاه یا بانک واقعی متصل نیستند.
