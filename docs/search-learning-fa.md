# جست‌وجوی محصول در دسکتاپ و موبایل

جست‌وجو داخل هدر، زنده و مبتنی بر تایپ است. `SearchProvider` یک نمونه state و Query را بین کادر دسکتاپ و پنجره موبایل مشترک می‌کند؛ دو رابط، دو جست‌وجوی مستقل ندارند.

**از تایپ تا نتیجه**

```text
input
  → مکث ۵۰۰ میلی‌ثانیه‌ای
  → debouncedInput
  → Query با کلید شامل عبارت
  → GET /api/catalog/products?search=...&per_page=10
  → WooCommerce Store API
  → نمایش نتیجه و لینک محصول
```

در [use-product-search.ts](D:/Projects2/nrh_store_nextjs/features/search/hooks/use-product-search.ts)، `input` متن فوری و `debouncedInput` متن بعد از مکث است. [useDebounce](D:/Projects2/nrh_store_nextjs/hooks/use-debounce.ts) با هر تغییر تایمر قبلی را پاک می‌کند. بنابراین تایپ سریع برای هر حرف درخواست جدا نمی‌سازد.

Query وقتی فعال است که متن پس از trim خالی نباشد. کلید `['get-search-result', debouncedInput]` باعث می‌شود پاسخ هر عبارت در کش خودش قرار بگیرد. `staleTime` یک دقیقه است؛ بقیه تنظیمات مانند retry از QueryClient عمومی به ارث می‌رسند.

[search.api.ts](D:/Projects2/nrh_store_nextjs/features/search/api/search.api.ts) از Axios با پایه `/api/catalog` استفاده می‌کند؛ همان BFF، پارامترها و مسیر را کنترل می‌کند. حداکثر ۱۰ نتیجه گرفته می‌شود و صفحه نتایج کامل یا صفحه‌بندی جست‌وجو ساخته نشده است.

**مالک هر وضعیت کیست؟**

| وضعیت | محل نگهداری |
| --- | --- |
| متن و بازبودن رابط | state در hook مشترک |
| نتیجه، دریافت اولیه و دریافت مجدد | TanStack Query |
| اعتبار محصول و موجودی | ووکامرس |
| انتخاب محصول | Link به URL داخلی تولیدشده با `productPath` |

هنگام دریافت اولیه skeleton نمایش داده می‌شود. اگر داده قبلی در دسترس باشد و Query در پس‌زمینه تازه شود، نشان «به‌روزرسانی نتایج» استفاده می‌شود. حالت متن خالی با نبودن نتیجه متفاوت است. بستن رابط، متن را لزوماً پاک نمی‌کند؛ دکمه پاک‌کردن این کار را انجام می‌دهد.

**تفاوت دو رابط**

[SearchField](D:/Projects2/nrh_store_nextjs/features/search/components/SearchField.tsx) فهرست زیر کادر را نشان می‌دهد. [SearchDialog](D:/Projects2/nrh_store_nextjs/features/search/components/SearchDialog.tsx) در موبایل کمتر از breakpoint `sm`، پنل تمام‌صفحه با `h-dvh`، focus اولیه، دکمه بستن و Escape دارد. hook در عرض کمتر از ۶۴۰ پیکسل اسکرول body را می‌بندد و هنگام cleanup مقدار قبلی را برمی‌گرداند.

این SearchDialog یک رابط سفارشی با role دیالوگ است؛ آن را با primitive دیالوگ Base UI که مدیریت focus مستقل دارد یکسان فرض نکن. با کلیک نتیجه، رابط بسته و محصول داخل Next باز می‌شود. دکمه آیکن جست‌وجو فعلاً handler ارسال یا submit جدا ندارد؛ شروع درخواست با تایپ و debounce است.

**محدودیت‌های مهم برای یادگیری**

- hook فعلی `error` Query را به UI برنمی‌گرداند؛ پیام اختصاصی خطای شبکه وجود ندارد و بعضی شکست‌ها ممکن است شبیه «نتیجه‌ای پیدا نشد» دیده شوند.
- signal مربوط به Query به Axios این مسیر پاس داده نشده است؛ قدیمی‌شدن عبارت لزوماً درخواست شبکه قبلی را قطع نمی‌کند. جدا بودن query key مانع جایگزینی پاسخ عبارت جدید با کش عبارت دیگر می‌شود.
- نمایش قیمت اینجا برچسب ثابت تومان دارد. انتقال به فروشگاه با ارز دیگر، formatter مشترک و توجه به minor unit می‌خواهد.
- تصاویر این بخش `<img>` هستند و هشدار lint دارند. این موضوع در این مرحله مستندسازی شده و کد آن تغییر نکرده است.

**تمرین:** سه حرف را سریع و سپس با فاصله بیش از نیم ثانیه تایپ کن و تعداد درخواست‌ها را بشمار. یک عبارت را دوباره جست‌وجو کن و تفاوت کش و refetch را ببین. قطع شبکه را فقط در DevTools محیط توسعه شبیه‌سازی کن و مشخص کن کدام حالت خطا در UI باید در توسعه بعدی اضافه شود.
